# 指标观测与流式诊断

## 目标与边界

服务端定义统一指标契约，agent 适配器、服务端组件和 Flutter 组件分别实现指标提供者。采集器只依赖接口，不识别 CLI、SDK 或具体 agent。当前阶段不改变输出节奏、滚动算法或 Markdown 展示。

现有功能分支 `feat/feedback-ui-fixes` 是本轮隔离工作区。开始前仅有用户未跟踪的 `.omc/`，不纳入改动或清理。

## 接口与数据流

`MetricsProvider` 暴露来源身份、`describeMetrics()` 与按游标读取的 `readMetrics()`。组件内部采用有界内存记录器；重复读取不删除记录。记录使用来源实例与递增序号去重，持久化成功后才推进采集游标。

服务端采集器每两秒读取所有来源，经 worker 写入独立的 `observability.db`。Flutter 采用对应 Dart 接口，本地采集后批量提交 HTTP。组件销毁后的尾部记录由采集器排干，观测失败不阻塞业务。

统一关联字段包括会话、回合起始序号、事件序号或范围及版本、设备、agent、模型、运行模式。所有耗时使用本地单调时钟，墙钟只用于时间范围查询。不同设备的时间不能直接相减宣称单向网络延迟。

标准指标描述包含名称、单位、类型、观测边界和可用状态。不支持、未采集和数值零分开表达。文本吞吐使用 UTF-16 码元数，不标作模型 token 数。禁止记录正文、提示词、工具参数或凭据。

## HTTP 接口

前缀为 `/observability/v1`，复用现有 HTTP/TLS 监听和 `x-aimi-token` 鉴权。设备身份取鉴权结果，不信任上传身份。

| 路径 | 职责 |
| --- | --- |
| `GET /catalog` | 指标来源、定义、单位、边界和可用性 |
| `POST /batches` | 有界、幂等的客户端上报，提交成功后确认 |
| `GET /series` | 按时间与维度查询分布、吞吐和数值 |
| `GET /traces` | 按会话、回合、事件序号查询详细记录 |
| `POST /baselines`、`GET /baselines` | 保存不可变基准摘要并进行环境一致性比较 |
| `GET /health` | 来源状态、采集故障、积压及丢样 |

默认查询最近十五分钟，最长三十天，明细使用游标分页。分位数从固定桶分布计算，不平均已有 P95。

## 默认预算

- 服务端采集队列最多 8192 条，客户端最多 2048 条，客户端单批最多 128 条。
- 明细保留三天，分钟聚合保留三十天，数据库预算 256 MiB。
- 基础统计持续采集，详细轨迹按回合采样 10%；受控诊断可使用完整采样。
- 来源超时、磁盘错误、网络错误与缓冲溢出独立隔离，丢样和缺失阶段必须可见。
- 基准记录版本、设备、刷新率、渲染器、运行模式、历史规模、场景和采样完整性，不同环境不能直接判为回归。

## 实现顺序与验收

1. 固化共享契约及有界记录器，验证重复读取、来源重启、非法记录和丢样。
2. 实现 worker 存储、采集、查询及 HTTP 集成，验证幂等、鉴权、保留期和故障隔离。
3. 接入 agent、EventBus、传输与 Flutter 组件，保持业务事件顺序和现有渲染行为。
4. 在 MuMu 使用当前源码 profile 构建，对比稀疏输出、密集输出、跟随开关、长历史和观测开关。
5. 保存可查询基准和诊断记录，执行全套检查与独立审查。

模拟器基准与手机验收分别报告。框架帧完成不等同于屏幕扫描输出完成；广播提交不等同于手机接收。

## 当前验证记录

- 真实隔离 Claude 适配器探针：CLI stdout 文本簇间隔 P95 分别为 991ms、440ms；stdout 到 SDK 交付 P95 为 0.20ms、0.37ms；服务端簇首到广播发送 P95 约 28ms。该结果确认服务端没有制造秒级空窗，但不区分 CLI 内部与 provider 缓冲。
- 协议测试：34 项通过。
- 服务端测试：51 个文件、322 项通过；观测 HTTP、worker SQLite、provider、Claude 会话指标均覆盖。
- Flutter 测试：198 项通过；`flutter analyze --no-pub` 无问题。
- `node tools/check-deps.mjs`：65 个文件扫描、0 个违规；`pnpm typecheck` 和 server build 通过。
- 更新后的运行服务已通过 TLS 鉴权冒烟：`GET /observability/v1/catalog` 返回 3 个来源，`GET /health` 报告采集来源 3、已落库记录 0、丢样 0；没有注入合成业务数据。
- MuMu profile APK 已构建并安装，版本 `1.3.4+20`。启动和打开缓存会话时 `gfxinfo` 记录 5 帧、1 个 janky frame（20%）；样本没有产生真实流式输出，不能作为流畅度结论。
- 观测版本 release APK 已更新为 `1.3.4+21` 并发布，发布清单与构建产物 SHA-256 均为 `c433f6582d0be58d84d09b63eafd82a49308abc5ad74481143515c229af057f4`；运行中的服务端已收到刷新通知。

因此，本轮交付的是观测底座和首批链路指标，尚未改变流式渲染算法。下一步应在 MuMu 连接到可用 agent 后，使用真实长回复和本地节奏回放查询 `client.connection.*`、`client.render.*`、`client.frame.*`、`client.scroll.*` 与 `claude.*` 指标，再决定修复落在上游、页面构建还是自动滚动。
