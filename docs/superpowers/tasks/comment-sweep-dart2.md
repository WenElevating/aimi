# 注释规范第二轮 — Dart 侧内容规则复查（apps/mobile）

## 背景
第一轮已完成大部分整改。本轮按用户完整规范的**内容规则**逐条复查（用户裁定：Dart 保持官方 dartdoc 叙述式，不引入 @param/@returns 标签），消灭残留的内容违规。

## 用户内容规范（逐字执行）

【函数/类注释】
- 第一句话用一句话说明"它做什么"（业务语言，不要叙述实现步骤）
- 参数：在叙述中说明含义、取值约束、单位、是否允许空值（Dart 惯例可用方括号引用参数名，如 ` Throws [X] if …`、`[token] 必须是…`）
- 返回值：说明含义和特殊取值（null/空列表/负数代表什么）；异步函数说明 Future 完成时的内容
- 异常：说明什么条件下抛什么；异步说明 Future 报错的条件下
- 有副作用（写库、发请求、修改入参、触发事件）必须说明
- 类/类型的每个字段：单行 `///` 说明含义和约束，不要只写"XX的ID"这类同义复述

【行内注释】
- 仅在逻辑不显然时添加，只解释"为什么"：业务规则、边界情况、兼容性、性能、规避的已知 bug
- 不要翻译代码字面含义；能从代码读出来的不写

【禁止项】
- 禁止出现"详见文档""参见 README""参考链接"等引用式说法，背景必须直接写出来
- 禁止用变量名/函数名叙述执行流程
- 禁止给命名已经清晰的简单代码加注释
- 禁止跨文件/跨栈引用（"与 TS 侧一致""对齐 zodFrames"）——把约束本身写出来（如：字段名与电脑端协议逐字一致，单方改名即解析失败）

【语言】中文；dartdoc 用 `///`（叙述式，非标签式——这是 Dart 官方惯例，用户已裁定保持）

## 执行规则
1. 逐文件通读 `apps/mobile/lib/**` 与 `apps/mobile/test/**` 的全部注释（不是只 grep——上一轮已清过显式违规，本轮要抓的是**不合规但不带显式违禁词**的注释：同义复述、字面翻译、缺失的参数约束/返回值/异常/副作用说明）。
2. 公开 API dartdoc：第一句话"它做什么"；参数约束、返回值特殊取值、抛错条件、副作用逐项自查，缺的补上，复述的删掉。
3. 字段注释：约束式（谁生成/取值范围/流转方向/失效条件），行尾不加句号。
4. 行内注释逐条判定：解释"为什么"的保留（可改写得更业务化）；字面翻译/复述/噪音删除；命名清晰的简单代码不加。

## 硬约束（违反=返工）
- **零代码改动**：只允许 `///` 与 `//` 行增删改；任何标识符/字符串/导入/逻辑一行不动。改后 `git diff -U0` 自查每个 hunk 仅触及注释。
- 公开 API dartdoc 覆盖率 100% 保持（可重写，不可删除消失）。
- 字符串字面量一概不动（上一轮已裁定：设置页提示、断言消息、reason: 文案属代码）。
