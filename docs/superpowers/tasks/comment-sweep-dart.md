# 注释规范整改 — Dart 侧（apps/mobile）

用户裁定的新注释规范（**本任务唯一规格，逐条执行**）：

【函数/类注释】
- 只说明：功能（一句话）、每个参数的含义与取值约束、返回值的含义、可能抛出的异常、副作用
- 用业务/领域语言描述，不要用代码里的变量名叙述执行流程
- 注释必须自包含，禁止出现"详见文档""参见README""参考XX链接"等引用式说法
- 不要复述实现细节

【行内注释】
- 仅在逻辑不显然时添加，且只解释"为什么这样做"（业务规则、边界情况、兼容性、性能原因）
- 不要翻译代码字面含义
- 没有必要的地方不加注释

【字段/类型注释（用户示例，语义照录）】
❌ 同义复述：/** 任务ID */ id
✅ 写出约束和含义：/** 全局唯一，由服务端生成，创建后不可修改 */
（字段注释 = 约束、生成规则、流转方向、失效条件；不是类型名的同义词）

【风格】中文；保持现有 dartdoc 块状格式（`///`，类/字段/函数一视同仁）。

## 硬约束（违反=返工）
1. **零代码改动**：只允许注释行（`///`、`//`）增删改。任何标识符、字符串字面量、import、类型、逻辑一行都不能动。
2. 公开 API 的 dartdoc 覆盖率保持 100%（数量不减）。
3. 自包含禁词清单——出现即违规，全部改写为自包含业务语言：
   - 文档引用：「§」「设计 」「计划 」「Task 」「G4」「C3/C4/C5」等编号引用
   - 流程引用：「controller」「裁决」「评审」「T13/T14/T15」「冻结」「ratification」「plan-mandated」
   - 跨文件引用：「对齐 zodFrames 语义」「同源」「与 TS 侧一致」「详见」「参见」——把约束本身写出来（如「字段名与电脑端协议逐字一致，任何一方单独改名都会造成解析失败」）
   - 里程碑黑话：「M0」「M1」「M1 换 Drift」「M1 重放补齐」——改写为当前行为描述：「本版本只保留在内存，应用退出即清空；后续版本将持久化到本机数据库」「断线期间的事件不回补，重新连接后从最新状态继续」
4. 行内注释清理：删除纯字面翻译与噪音（`// tick++`、`// 空实现`）；保留真 why（如「服务端会话号与本地会话号可能不一致，比较必须用服务端返回的 id」）。
5. 测试文件同样整改：断言目的用业务语言描述。
