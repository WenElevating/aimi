## 用户完整规范（逐字执行，优先级最高）

【函数/类/接口注释】
- 第一句话用一句话说明"它做什么"（业务语言，不要叙述实现步骤）
- @param 说明参数的含义、取值约束、单位、是否允许空值；不要写类型（TS 签名已有）
- @returns 说明返回值的含义和特殊取值（如 null/空数组/-1 代表什么）；异步函数说明 resolve 的内容
- @throws 说明什么条件下抛出什么错误；异步函数说明 reject 的条件
- 有副作用（写库、发请求、修改入参、触发事件）必须说明
- 接口/类型的每个字段，用单行 /** */ 说明含义和约束，不要只写"XX的ID"这类同义复述

【行内注释】
- 仅在逻辑不显然时添加，只解释"为什么"：业务规则、边界情况、兼容性、性能、规避的已知 bug
- 不要翻译代码字面含义；能从代码读出来的不写

【禁止项】
- 禁止在注释里重复类型（如 @param {string}）——**@throws 后的大括号异常类型允许**（如 `@throws {RangeError} …`）
- 禁止出现"详见文档""参见 README""参考链接"等引用式说法，背景必须直接写出来
- 禁止用变量名/函数名叙述执行流程
- 禁止给命名已经清晰的简单代码加注释

【语言】中文

## 用户示例（样式校准，照此执行）
✅ 函数：
```
/**
 * 计算订单应付总额（已扣除优惠）。
 *
 * @param items - 订单商品，不能为空；每项的单价和数量均需为非负数
 * @param coupon - 优惠券；传 null 表示不使用优惠
 * @returns 应付金额，单位为分，最低为 0（优惠不会让总额变成负数）
 * @throws {RangeError} 商品列表为空，或存在负数单价/数量时抛出
 */
```
✅ 异步（@throws 说明 reject 条件）：见基准样例 publish/subscribe 的写法；永不 reject 的异步要显式写"不会 reject"。
✅ 字段（约束与含义，不是同义复述；行尾不加句号）：
```
/** 全局唯一，由服务端生成，创建后不可修改 */
id: string;
```
✅ 行内（解释为什么，不复述代码）：
```
// 第三方接口被限流后通常要等一分钟才恢复，重试超过 3 次基本无意义，直接放弃
```

## 执行规则
1. 每个导出函数/方法/类/接口 + 语义不显然的私有成员：第一句话"它做什么"（业务语言），随后标签按需排列（@param→@returns→@throws→副作用说明）。副作用写法：以"副作用：…"起头的普通句子。
2. 接口/类型字段：单行 `/** */` 约束式。字段注释是"这个值的规则"（谁生成/取值范围/单向流转/失效条件），不是类型名的同义词。
3. 标签缺一不可的判断：无参函数不写 @param；永不抛错且语义显然可不写 @throws；但**凡有 await 的导出函数必须说明 resolve 内容；凡写库/触发事件/修改入参必须说明副作用**。
4. 私有小函数：同样规则，允许更紧凑；命名已清晰的简单代码不加注释。
5. 第一轮残留专项排查（grep 逐个确认）：括号内跨文件符号引用（（接 X）（对齐 X）（见 X））、英文术语残留（per-slot、override、fake timers→假定时器 等，技术名词无恰当中文时可保留原文但先尝试意译）、箭头链执行流程叙述（A → B → C）。
6. 测试文件同等对待：测试辅助函数/类的注释按完整规范；断言目的注释用业务语言（不引用编号）。
7. `tools/check-deps.mjs`（JS 无类型签名）：内容规则一致，函数注释可用 @param 标签但不带大括号类型。
