# aimi M1「核心闭环」设计文档

> 承接 v1 设计（`2026-10-17-aimi-v1-design.md`）里程碑表第二行。M0（骨架跑通）已验收
> （8 项冒烟 + CI 全绿 + AC 六条，2026-10-18 收口）。本文档不重复 v1 已定内容，
> 只把"核心闭环"落成 M1 可实施的设计；具体实现由后续 plan 决定。

---

## 1. 意图与背景（Intent & Why）

M0 验证了核心假设：手机能看到 claude 实时流并打断。但当下的系统离"日用"还差三件事：

1. **审批流缺失**：agent 请求权限或提问时，手机端不可见、不可答——人必须守在电脑前；
2. **通知缺失**：退出 app 即失联，任务完成/卡住/请求审批都无人知晓；
3. **可靠性缺口**：断线重连丢事件（手机端内存镜像+无重放）、配对手填三字段且无设备管理
   （token 泄露无法吊销）、server 崩溃不自启、agent 异常无法续接上下文。

这三件事正是 v1 里程碑表"核心闭环"的出口三句话：**家里 LAN：新建任务→实时流→审批→完成
全流程；退出 app 后通知仍响（前台服务）；重启电脑后可续接。**

M1 同时收口 M0 冒烟发现的 5 条缺陷（3 条 UI 呈现 + 2 条生命周期语义——见 §5.1/§5.11），
不单独立项〔对话裁决〕。

值得强调：v1 设计在 M0 期已大批预埋，M1 的主体是**接线与两端行为**，不是协议重设计——

- 协议层已预留：`AgentState` 含 `waiting_approval`/`waiting_input`/`stopped`；
  通知分类枚举（pending_approval/pending_question/finished/failed/stalled）已定义；
  `ping/pong` 心跳帧、`bye` 帧、`hello` 的 resume 字段位均已存在；
- 手机端已实现：重连退避（1s/2s 积极重试→30s 封顶+250ms 抖动）、心跳判死、
  徽标 LAN/重连中/离线三态（M1 增"中继"第四态）；
- 服务端已铺：`sessions.resume_hint` 列（M1 注释预留）、claude `--resume` spawn 参数、
  `SessionManager` adopt 通道——唯独 claude 会话 id 未捕获落库、审批/提问事件未接线。

## 2. 目标 / 非目标 / 反目标

### 2.1 目标（可验收）

- **G1 审批/提问全流程**：agent 权限请求/提问在手机时间线呈现为可答复卡片
  （once/always/reject / 自由文本），答复经服务端送达 agent 继续运行；
  app 未在桌面前台时，可从通知栏 action 直接批准/拒绝〔承 v1 §5.6 §5.7〕。
- **G2 通知触达**：app 退后台甚至被杀后，通知仍送达（前台服务长连接承载，
  不依赖任何系统推送商，正常网络 ≤10s P95）；通知按事件分类在设置中启停。
- **G3 可靠续接**：断线重连后缺口事件补发（零丢失、≥500 events/s）；
  手机本地镜像持久化（杀 app 不丢，离线可读）；agent/server 崩溃后可对既有会话续接
  （上下文保留）；重启电脑后 server 自启、手机可续接。
- **G4 安全配对与管理**：终端配对码 QR 扫码即连（免手填）；设备 token 只存手机
  secure_storage 与 server 端哈希；`devices` 列表 / `revoke` 即时断连；
  单设备锁防同 token 并发双头写。
- **G5 后台韧性**：server 崩溃自动重启（Windows 任务计划）；手机重启后前台服务自恢复
  （承接 v1 G 项承诺：前台服务恢复 ≤5 min）。

### 2.2 非目标（v1 既定 + M1 明确不做）

- iOS 链条（v1 C3，后置追平）；
- relay 部署上线（v1 Q6：域名/规格确认后启用——M1 只交**代码 + 部署物 + 本机/LAN 仿测**）；
- mDNS 自动发现（配对 QR 已携带 LAN 地址与 relay 地址，无新增价值）；
- codex / opencode / zcode 适配器（全量日用段）；
- UI 视觉专项（v1 Q7：先功能后视觉；本文只约束功能布局与状态）；
- 跨设备双头写仲裁（超出同 token 互踢的多设备语义归 v1.1）；
- E2E 加密 / FTS 搜索 / 未读与通知偏好细化 / 本地过滤搜索（v1.1 或全量日用段）；
- 磁盘满 / DB 损坏 / 推送 token 失效等追加异常（v1 §6 追加段归全量日用段细化；
  M1 仅保证 DB 写失败不中断流与日志）；
- **附件（send.files）**〔对话裁决 2026-10-18：后续实现〕——M1 不做，占位提示文案改为
  "后续里程碑接入"消除撒谎 UI（顺手修，任意段）。

### 2.3 反目标（出现即算失败）

- 审批请求**静默丢失**（不呈现、也不提示失效——v1 §6 #2 红线）；
- 通知依赖第三方服务器组件（Firebase/APNs——C10 反目标承接）；
- 手机端能升 `permissionMode`（§5.5 守卫反向）；
- 同 token 多连接双头写状态（单设备锁失效）；
- 续接后同一会话出现第二个存活 agent 进程（冒烟 F5 孤儿进程复发）；
- 打断/被停止的会话被标为"失败"（"已停止"≠"已失败"，语义混淆回流——冒烟 F3）。

## 5. 已决定的组件设计（as decided，M1 具体化）

### 5.1 会话生命周期与续接（服务端）

- **打断/停止语义**：用户打断或 agent 被停止 → 回合最终 state=`stopped`（枚举已存在），
  手机端文案"已停止"；只有异常（崩溃/管道断裂）才标 `failed`。
- **回合门 → 会话门〔对话裁决〕**：`send` 的可接受条件从"回合进行中"放宽为
  "会话可续"：
  - agent 进程存活（上回合 finished/stopped 但进程仍健在——冒烟证实 claude CLI
    天生多回合）→ 直接开新回合，免冷启动（首轮实测 15-20s）；
  - 进程已死 → 以 `sessions.resume_hint` spawn `--resume {hint}` 续接（底座已铺，
    M1 补"捕获→落库→取用"链）；
  - 不可续接（无 resume_hint 且进程死）→ 会话只读（"已过期"态），不可发消息。
- **resume_hint 落库**：适配器启动握手捕获 claude 会话 id → 更新 `sessions.resume_hint`。
- **续接的用户视图**：可续接的会话卡片有"续接"入口；续接后的新回合在时间线中以
  回合分隔线与旧内容区隔，旧内容不动。
- **PID 台账与孤儿清理**：spawn 时记录 {sessionId, 进程 pid}；server 正常停机
  killTree 全清（承 M0 冒烟审计的 no-op 修复）；server 异常重启后启动清点：
  台账 pid 若已无主（launch 上下文丢失）→ 终止并记录审计——M0 F5 孤儿进程的防线。
- **适配器协议探测（异常 #6 落地）**：适配器启动握手探测 CLI 协议可获得性；
  探测失败/不兼容 → 该 agent 在手机看板标灰"暂不可用"（新建会话不可选），
  故障隔离到单 agent——M0 未做，M1 落地（探测方式即 Q-M1-1 spike 一部分）。

### 5.2 缺口重放（协议 + 服务端）

- `hello` 携带 `resume{[sessionId]: lastCursor}`（字段位已预留）；
- server 依 `events` 表 seq>cursor 逐会话补发，直接沿用现有 `session.event` 帧序列
  （不新造帧型），补发顺序即 seq 序；
- 手机端镜像逐事件记录 lastCursor，重放完成 = 追平服务端 last_seq；
- 补发吞吐 ≥500 events/s（e2e 断言，见 §7）；
- 缺口超限（>10,000 事件，**按每会话缺口计**）时 server 不逐帧补发，改发
  "重放过大"通知 + 该会话时间线顶部"此段历史不可读"标注 + 会话列表全量
  刷新兜底〔我的决定——v1 未细化超限行为，可被否决〕；
- **重放与实时并发排序**：同一连接上 server 保证 seq 全序——重放以快照切点为界，
  先补发已入库缺口、再无缝续上实时广播（实施机制留实现者），手机端现有
  "非连续 seq 丢弃"逻辑不被触发——零丢失承诺由服务端全序兑现；e2e 断言按该语义构造；
- **重放基线**：手机无 lastCursor（全新安装/镜像清空）视为从 0 全量拉取该会话
  （与缺口同级受上限规制）〔我的决定〕——"离线可读"承诺即"曾同步过即离线可读"。

### 5.3 配对与设备管理

- **`aimi-server pair`**：终端打印配对 QR，内容 = serverId + LAN 地址 + relay 地址 +
  8 位一次性配对码（5 min 有效、用一次即焚——v1 §5.4 原文）；
  **配对通道〔我的决定，安全面等价、协议内最简〕**：未持 token 的手机以
  `hello{pairingCode, deviceName}` 形式接入（server 校验成功后于本连接下发配对
  响应帧并完成 token 交换，此后按正式设备身份续用该连接/重连）——server 端必须
  对配对提交做失败限速（防 8 位码爆破）；安全评审要点：该通道是无凭据可提交的服务端
  入口，其暴露面 = 码时效 + 一次即焚 + 失败限速 + 局域网边界；
  手机端 Settings"扫码配对" → 提交 → server 校验码 → 生成 32 字节随机设备 token
  → **明文 token 仅在配对响应出现一次**：server 端只存 SHA-256，
  手机端存 secure_storage（Keystore/Keychain）；设备名随配对请求携带（默认机型名，可改）。
- **devices 表语义升级**：M0 的 `lan-default` 预留行退位为遗留迁移项；每设备一行
  （id / name / token_sha256 / last_seen_at / revoked_at）；
  **lan-token.txt 终态〔我的决定〕**：保留为 LAN bootstrap 通道（手填入口的 token 来源），
  但 `revoke` 覆盖该身份时**同步报废 token 文件**（删除 + 审计），
  消除"吊销后 server 重启从文件原样复活设备行"的漏洞——revoke 必须持久。
- **`aimi-server devices`**：列出租户设备（名称 + 最后活跃时间）；
  **`aimi-server revoke <device>`**：即时失效——活连接立即断（`bye{revoked}`）+
  审计记录；被吊销的手机端提示"设备已被移除"并停止自动重连。
- **审计细分**：`auth.pair` / `auth.revoke`（M0 死枚举接通）入 audit 表 + audit.log；
  带 device 上下文的命令审计语义保持 M0 口径。
- **手填三字段入口**降级为 Settings 折叠的"高级"备用入口，LAN 直连能力保留。

### 5.4 单设备锁

- 同 token 并发连接：后登者生效，先登者收 `bye{taken_over}` 后连接关闭；
- 被踢端 UI 提示"已在别处接管"，**停止自动重连**（防乒乓），由人工重开；
- 不同 token 并存允许；限速（每设备 ≤10 cmd/s，超限排队不丢弃）与审计对
  跨设备双头写兜底〔对话裁决〕。

### 5.5 权限审批与提问（P2 核心链路）

- 适配器接线（claude 优先，stream-json 控制通道——M0 interrupt 已用同路验证）：
  - 权限请求 → 域事件 `permission.request`（tool、请求摘要、可选项），会话 state
    → `waiting_approval`，落库广播；
  - 提问 → `question.request`（问题、可选建议项），state → `waiting_input`；
- 手机端时间线插入**审批卡**（once / always / reject 三键）与**提问卡**
  （文本输入 + 建议chip）；答复作为 session.command 变体回传
  （`permission.response` / `question.response`，clientId 幂等照旧）；
- **晚到/失效**：state 非 waiting_* 时收到响应 → notice"审批已失效/提问已失效"
  时间线显式标注，卡片转时效性样式（灰化）——不静默吞、不代答（v1 Q3 代决）；
  若 agent 自身对权限请求有超时，以 agent 的失效为准映射同一时效卡；
- **waiting 态中断的收口〔我的决定〕**：会话在 waiting_* 时进程死亡/server 重启，
  resume 续接后 agent 不重放该请求（claude 无此机制）——原挂起卡**自动转时效卡**
  标注"因会话中断失效"；这不是静默丢失（红线内），用户续接重发任务即可重新触发；
- **权限守卫的落地面〔我的决定〕**：M1 无中途变更 permissionMode 的命令帧——
  守卫=创建时静态白名单（手机端可选集 = 安全降序子集 {default, plan}；
  更宽松模式仅经 server 侧配置/CLI 设置）；越权（手机提交白名单外模式）→
  server 拒绝 error + 审计。Q-M1-2 的降序表为将来新增中途变更命令帧时的前置约束，
  M1 不依赖。
- 具体权限请求/答复的 stream-json 消息形态属实现期核实项（§9 Q-M1-1 spike）
  【2026-10-18 已核实：形态 = MCP 审批闸路由（plan Task 7 全文）——审批请求不进 stream-json，由 CLI
  拉起的闸进程承接；CLI 对闸无内置超时，"agent 自身失效"不存在，挂起卡的时效语义由
  手机操作/会话中断两个来源产生】；提问通道 headless 下不存在（FACT5），提问卡协议保留待其他 agent。

### 5.6 watchdog stalled

- running 会话超过阈值（默认 10 min，server 配置可调）无任何新事件
  → `notice{stalled}`（通知分类默认关）+ 时间线内提示条"可能卡住"；
- 仅提示，不自动打断、不改 state（v1 §6 #10 承接）；任何新事件到达即解除提示。

### 5.7 前台服务与通知分类（手机端，Android）

- **前台服务**持有到 LAN/relay 的 WS 长连接；常驻状态栏通知明示"aimi 在守护运行"
  （点击直达会话看板）；app 被杀/被回收时服务与通知维持监控职责（前台服务生命周期
  的实现路线属 §8 留给实现者，验收以"退出 app 通知仍响"为准）；
- **通知派生与过滤〔对话裁决 2026-10-18：本地派生〕**：通知由手机端从事件流
  **本地识别分类并合成**（协议零改动——server 不新增通知帧、偏好不上 server，
  relay 保持最哑）；进行中的事件分类映射：permission.request→pending_approval、
  question.request→pending_question、finished/failed→同名、notice{stalled}→
  stalled（识别映射写进适配器常量）；"按分类启停"偏好存手机本地设置；
  （v1 §5.7 "server 分类路由下发"字面以"本地派生"演进解释——送达承诺不变：
  本地渲染、不经第三方）；
- **形态**：本地渲染（内容不经过第三方）；点通知 → GoRouter 深链直达会话并补齐缺口；
- **通知分类默认**：pending_approval / pending_question / finished / failed 默认开；
  stalled 默认关（设置页按分类启停，偏好存手机本地）；
- **电池白名单引导**：Settings 内置引导页——跳转系统电池优化白名单 +
  覆盖 Top 4 厂商（小米/华为/OPPO/vivo）的后台管控说明 + 通用 Android 提示
  〔我的决定——覆盖面可按真机清单调整〕；
- **开机自启**：BOOT_COMPLETED → 恢复前台服务；Settings 提供"开机自启"开关（默认开）；
- **连接状态机**：承 M0 退避（1s/2s 积极 → 30s 封顶 + 250ms 抖动）+ 心跳判死
  （15s×2 拍 ≤45s 检出）；前台服务与 UI 共用同一连接状态与徽标。

### 5.8 通知 action 与深链

- pending 类通知带"批准 / 拒绝"按钮（Android 通知 action）：
  点击 → 拉起 app → GoRouter 直达会话 → **自动提交审批命令** → 通知消除；
  已失效的审批深链后呈现时效卡（不重复提交）〔承 v1 §5.6"通知即命令入口"〕。

### 5.9 relay 与双链路

- **apps/relay**：哑管道（v1 §5.5）——两端 token 校验、按 serverId 配对路由、
  原样转发帧（不解析协议，协议升级不需要动 relay）、心跳保活；
- **链路拓扑**：server 主动拨出 relay（拨入采用独立 server-token，服务器配置持有，
  不复用设备 token——v1 §6 附件通道细化既定）；手机 ↔ relay ↔ server；
- **relay 宕机**：server 指数退避重拨（v1 §6 #5）；手机连 relay 失败 3 次 →
  提示用 LAN（横幅提示，自动回到 LAN 优先重试）；
- **手机双链路迁移**：同时持有 LAN + relay 地址（配对 QR / welcome 下发）；
  断连重试先试 LAN，3 秒内不通切 relay；徽标四态 **LAN / 中继 / 离线 / 重连中**
  （M0 已有三态，M1 增"中继"）；
  双链路可双向迁移（relay 通了→恢复→LAN 恢复→迁回）；
  LAN→relay 迁移 ≤3 s（e2e 断言，§7）；
- **部署物**：`tools/deploy/relay/`——systemd unit + Caddy（TLS 终结在前）+ 安装脚本；
  **验收 = 本机/LAN 仿测**（本机起 relay → server 拨入 → 手机连 relay 全流程），
  真部署归全量日用段（Q6）。

### 5.10 Windows 自启（server 侧）

- `tools/windows`：任务计划注册/卸载脚本（开机自启 + 崩溃自动重启）；
- AC：注册后重启电脑 → `status` 正常 + 手机能连（用户手动验证一次）；
- AC-M0-6 已实证崩溃可恢复（WAL 自恢复），M1 补自动化外壳。

### 5.11 时间线呈现修复（冒烟 #3/#4/#5）

- **自动滚底**：有新事件追加时自动滚到底；用户向上翻阅 → 停止自动滚（不抢位置），
  回到底部后恢复跟随〔我的决定——交互口径〕；
- **输出摘录**：工具卡（Bash/Write 等）的输出区取 tool_result 摘录
  （截断承 v1：>8 KB → 摘录+截断标记——M0 服务端已做截断，手机端把摘录渲染出来）；
- **卡片状态**：会话卡片状态一律读会话 state（服务端权威落地值）；
  error notice 只出"错误条"，不染改卡片状态色（M0 F8 修复口径）。

### 5.12 协议 Dart 生成管道

- `packages/protocol`（TS/zod 单一源）→ 生成 Dart 帧模型，替代 M0 手写 `frame_dto.dart`
  镜像；CI 增漂移检查（生成产物与提交一致才过——保证 Dart 端不会静默漂移）；
- 生成路线选型（quicktype 或自研 zod 扫描）留给实现者（§8）。

### 5.13 手机端本地镜像（Drift）

- sessions/events 落本地镜像库（v1 §5.6 既定选 Drift；schema/迁移留实现者）；
  lastCursor 随镜像持久；
- 冷启动顺序：本地镜像先渲染 → 连接 → welcome 全量校准 → 缺口重放补齐；
- 杀 app 后看板/时间线**离线可读**（镜像仍在）——"可靠续接"的手机侧地基；
- M0 内存镜像退役为镜像库上的读缓存层（演进方式留实现者）。
