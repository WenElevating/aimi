# 需求方案：会话列表搜索

- 来源反馈：feedback #20261025-204503-8b9db4（第 2 点）
- 用户原话：「某个项目的会话比较多，这样显示查找比较费劲」
- 方案日期：2026-10-26
- 状态：仅方案，未实现；合并权限归人工

## 1. 需求概述

用户在某个项目下积累了大量会话，看板按项目分组展示后，组内会话仍需肉眼逐条扫描才能找到目标会话，希望提供快速定位手段。理解：需要一个按关键字过滤会话列表的能力（按项目名/会话标识等元数据匹配），而非新增会话管理操作。

## 2. 价值与合理性

- 解决的问题：多会话（数十个以上）时定位效率低；这是"远程 agent 会话监控"工具的核心检索体验。
- 目标用户：同时跑多个项目、多会话的重度用户（本反馈用户即典型）。
- 与产品定位一致性：会话是核心对象，可检索性是监控工具的基本能力，与 design.md「克制」原则不冲突（可做成隐藏式入口）。
- 优先级建议：中（体验优化，非功能阻断；低于会话页稳定性类问题）。

## 4. 方案设计（推荐：移动端本地过滤）

功能流程：

1. 看板筛选 chips 行尾增加搜索图标；点击展开一行搜索输入框（再点或清空收起），避免常驻输入框挤占列表空间（design.md 克制原则）。
2. 输入关键字后，`filteredSessionsProvider`（新增派生 provider）对 cache 中的 `SessionMetaDto` 做本地过滤：cwd 全路径、项目名（`projectNameOf(cwd)`）、状态名，大小写不敏感子串匹配。
3. 过滤结果与状态筛选 chips 为 AND 组合（先状态后关键字）；分组逻辑不变（`_groupedRows` 输入换为过滤后列表）。
4. 无匹配时展示空态文案（如「没有匹配的会话」），复用现有空态样式。

交互/界面：搜索框样式复用现有输入组件；图标用 `AimiIcons` 现有搜索图标（若无则用最接近的现有图标，不新增图标资源）。

数据结构与接口变更：**无协议变更、无服务端变更、无本地 DB 变更**（纯内存派生状态）。

涉及文件与模块：

- `apps/mobile/lib/app/providers.dart`：新增 `sessionSearchQueryProvider` + `filteredSessionsProvider`。
- `apps/mobile/lib/ui/dashboard/dashboard_screen.dart`：搜索入口、输入行、列表数据源切换。
- `apps/mobile/test/domain/`（或 `test/ui/`）：过滤逻辑与 UI 测试。

## 5. 备选方案及取舍

**备选：服务端搜索协议帧**（新增 `session.list` 查询帧带 query 参数，服务端 SQL 过滤）。

- 优点：会话量极大（数百+）时内存与传输友好；为未来跨设备检索铺路。
- 缺点：动协议层（`packages/protocol` + Dart DTO 两侧同步）、welcome 快照架构要改、服务端测试全套；当前会话量级下收益为零。
- 取舍：推荐本地过滤起步；若未来单机会话量达到数百条以上、welcome 快照出现可感知延迟，再演进为协议帧方案。

## 6. 风险与影响

- 兼容性：纯客户端 UI 行为，旧版本无感知，无迁移。
- 性能：全量快照内存过滤 O(n)，n 为数百级时可忽略；输入防抖 200ms 避免每键重算。
- 对现有功能影响：筛选 chips 语义叠加需测试覆盖；分组标题计数应随过滤结果更新，避免计数与列表不一致。
- 安全：无（本地数据本地过滤，不上传）。
