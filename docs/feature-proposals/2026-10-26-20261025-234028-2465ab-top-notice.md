# 需求方案：更新通知顶部化与主题化

- 来源反馈：feedback #20261025-234028-2465ab
- 用户原话：「现在的通知紧贴着应用连接状态，我希望改为顶部提示，根据主题显示通知背景和字体颜色。另外现在"当前已是最新版本"的提示也按上面的要求调整，现在很丑」
- 方案日期：2026-10-26
- 状态：仅方案，未实现；合并权限归人工

## 1. 需求概述

两点诉求：

1. 看板页「发现新版本」通知（当前是紧贴连接状态栏下方的内联横幅）改为从屏幕顶部滑入的浮层提示，背景与文字颜色跟随明暗主题。
2. 「当前已是最新版本」顶部轻提示（`AimiTopToast`）按同样的主题化标准调整样式（用户认为目前不好看）。

理解：把更新相关通知统一收敛为「顶部浮层 + 主题 token 配色」的通知体系，替代内联横幅。

## 2. 价值与合理性

- 解决的问题：内联横幅挤压看板列表空间、位置突兀（用户原话「紧贴着应用连接状态」）；配色未形成体系。
- 目标用户：所有收到服务端更新推送的用户。
- 与产品定位一致性：更新通知是服务端推送链路的可见面（`publish-apk` → 在线手机），呈现质量直接影响发版触达。
- 优先级建议：中（体验改造；其中暗色下「当前已是最新版本」文字不可见为实际缺陷，已由修复分支 fix/feedback-20261025-234028-2465ab-top-toast-dark 单独修复）。

## 4. 方案设计

新增「可停留顶部通知」形态，收敛进既有顶部浮层体系：

1. **组件**：在 `aimi_primitives.dart` 新增 `AimiTopNotice`（或扩展 `showAimiTopToast` 增加 `sticky` 参数）——与 toast 同样从状态栏下滑入、挂 rootOverlay，区别：
   - 不自动消失：停留至用户点击（跳设置页处理更新）或手动关闭（右侧关闭按钮，热区 ≥44）；
   - 同一时刻仅一条（复用 `_activeTopToast` 的互斥逻辑）；
   - 配色走参数化 token：更新通知用 `ai.greenSoft` 底 + `ai.ink` 字 + `ai.line` 边（亮暗自动适配），不再写死 ink 底。
2. **接入**：`dashboard_screen.dart` 移除内联 `_UpdateBanner`，改为监听 `appUpdaterProvider.phase == UpdatePhase.available` 时弹出顶部通知；点击进入设置页（与现横幅行为一致）。
3. **重复打扰控制**：同一目标版本号只自动弹出一次（记入内存态/轻量持久态），用户忽略后不重复弹，可在设置页查看更新（现有入口保留）。
4. **重连横幅**：`_ReconnectingBanner` 用户未点名，本次不动（列为可选项，见待确认）。
5. **「当前已是最新版本」样式调整**：在修复分支（对比度修复）基础上微调：沿用 ink 底 + canvas 字的 pill，优化内边距与阴影层级（对齐 `AimiShadow.float`），具体以设计评审为准——用户「很丑」的具体指向需澄清。

数据结构与接口变更：无协议/服务端变更；纯移动端 UI。

涉及文件：`aimi_primitives.dart`（新组件）、`dashboard_screen.dart`（接入 + 删内联横幅）、`settings_screen.dart`（可选微调）、`test/ui/widgets/top_notice_test.dart`（新测试）。

## 5. 备选方案及取舍

**备选：仅美化现有内联横幅**（加大与 Header 的间距、统一 token 配色、加关闭按钮）。

- 优点：改动最小（约 0.25 天），零新组件。
- 缺点：不满足用户「改为顶部提示」的明确诉求；内联横幅仍占列表空间。
- 取舍：推荐顶部化（用户诉求明确且顶部浮层基建 AimiTopToast 已存在，边际成本低）。

## 6. 风险与影响

- 兼容性：纯客户端 UI；服务端推送协议不变。
- 遮挡风险：顶部浮层覆盖看板首屏内容——必须提供关闭；停留策略见方案第 3 点。
- 行为风险：每次进看板都弹会造成打扰——用「同版本号只弹一次」控制；phase 持久 available 时的边缘状态需测试。
- 可访问性：关闭按钮与整条可点击热区 ≥44；语义标签齐全（对齐 AimiIconButton 约定）。
